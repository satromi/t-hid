# ゲームパッド

キーボードを、キーボードとゲームパッドを兼ねる1台のUSB機器にします。PCからは、キーボードとは別にゲームコントローラが1台つながったように見えます。キーマップに置いたゲームパッド用のキーで、ボタン、十字キー、スティックを操作します。

ドライバのインストールは要りません。Windows、Linux、macOS、超漢字(usbplus)の標準のHIDドライバが、汎用のゲームパッドとして読みます。

| 項目 | 内容 |
| --- | --- |
| ボタン | 32個(名前付きのキーは13個、番号指定で32個すべて) |
| 十字キー | ハットスイッチ(8方向)。逆向きを同時に押すと打ち消して中立になります |
| スティック | 左(X/Y)と右(Z/Rz)。キーを押している間だけ端まで倒します |
| 対応ボード | RP2040(TL Splitのマスター、片手ビルド)、NUCLEO-H533RE(キーボードブレイン) |
| キーボード | これまでどおり使えます。ゲームパッドのキーはキーボードの入力にはなりません |

## ビルド

ビルドのオプション`GAMEPAD=1`で有効になります。既定は無効で、そのときのUSBの構成はキーボードだけ(H533ではキーボードとU2F)です。`GAMEPAD`を変えたときは、`make clean`してからビルドしてください。

ゲームパッドのレイヤーを入れたキーマップ`gamepad`を用意しています。

RP2040(TL Split)の場合:

```bash
bash setup.sh
cd mtk3_bsp/build_make
make TARGET=_PICO_RP2040_ clean
make TARGET=_PICO_RP2040_ KEYMAP=gamepad GAMEPAD=1 split
#   → mtkernel_3_master_gamepad.uf2 / mtkernel_3_slave_gamepad.uf2
```

USBでPCにつなぐのはマスターだけなので、ゲームパッドが関係するのもマスターです。

NUCLEO-H533RE(キーボードブレイン)の場合:

```bash
bash setup.sh
cd build_bsp2
make clean && make KEYMAP=gamepad GAMEPAD=1
```

`NET=0`、`U2F=0`、`TZ=1`と組み合わせられます。

## 使い方

キーマップ`gamepad`では、FN+Gでゲームパッドのレイヤーに切り替わり、もう一度FN+Gで戻ります。ゲームパッドのレイヤーでは次のキーがゲームパッドになり、それ以外のキーはキーボードとして使えます。

| キー | ゲームパッド |
| --- | --- |
| W/A/S/D | 十字キー(上/左/下/右) |
| I/J/K/L | X/Y/B/A(上X、左Y、下B、右Aの菱形) |
| Q/E | L/R |
| U/O | L2/R2 |
| TAB/ENT | Select/Start |
| 矢印キー | 左スティック |

配置を変えるときは、`app_program/keyboard/keymaps/gamepad/keymap.c`をコピーして自分のキーマップ(`keymaps/<名前>/keymap.c`)を作り、`KEYMAP=<名前>`でビルドします。キーマップの書き方は[keyboard.md](keyboard.md)を参照してください。

### キーマップで使える名前

`app_program/keyboard/kb_hid_keycodes.h`で定義しています。

| 名前 | 内容 |
| --- | --- |
| `JS_Y` `JS_B` `JS_A` `JS_X` | ボタン1/2/3/4 |
| `JS_L` `JS_R` `JS_L2` `JS_R2` | ボタン5/6/7/8 |
| `JS_SELECT` `JS_START` | ボタン9/10 |
| `JS_L3` `JS_R3` `JS_HOME` | ボタン11/12/13 |
| `JS_BTN(n)` | ボタンn+1(n=0〜31) |
| `JS_UP` `JS_DOWN` `JS_LEFT` `JS_RGHT` | 十字キー(ハットスイッチ) |
| `JS_LS_UP` `JS_LS_DOWN` `JS_LS_LEFT` `JS_LS_RGHT` | 左スティック(X/Y) |
| `JS_RS_UP` `JS_RS_DOWN` `JS_RS_LEFT` `JS_RS_RGHT` | 右スティック(Z/Rz) |

ボタンの番号は、汎用のHIDゲームパッドに多い並び(1 Y、2 B、3 A、4 X、5 L、6 R、9 Select、10 Start)に合わせています。エミュレータなど、ボタンの番号で読むアプリの多くがこの並びを前提にしているためです。

`GAMEPAD=1`なしでビルドすると、`JS_*`のキーは何も送りません(キーボードの入力にもなりません)。

## 動作の確かめ方

- Windows:「USB ゲーム コントローラーのセットアップ」(`joy.cpl`)に現れます。プロパティで、ボタン、ハット、軸の動きを見られます。
- Linux:`evtest`や`jstest /dev/input/js0`で見られます。
- 超漢字(usbplus):「ゲームパッド」デバイスに現れます。`padctl`で一覧と入力の記録を見られます。
- ブラウザ:Gamepad APIを使うテストページで、ボタンと軸の動きを見られます。

## 仕組み

### USBの構成

`GAMEPAD=1`のときは、キーボード(とU2F)の後ろにゲームパッドのインタフェースを1つ加えた複合デバイスになります。

| インタフェース | RP2040 | H533(U2Fあり) | エンドポイント |
| --- | --- | --- | --- |
| キーボード(Boot Protocol) | 0 | 0 | EP1 IN、8バイト、10ms |
| FIDO U2F(CTAPHID) | なし | 1 | EP2 IN/OUT、64バイト |
| ゲームパッド | 1 | 2 | EP3 IN、16バイト、2ms |

ゲームパッドのインタフェースはブートデバイスではありません(サブクラス0)。BIOSやUEFIの画面では、キーボードだけが使われます。

### レポート

レポートは9バイトで、レポートIDは付けません。

| バイト | 内容 |
| --- | --- |
| 0〜3 | ボタン1〜32(1ビットずつ) |
| 4 | 下位4ビットがハット。0が上、1が右上と時計回りに7(左上)まで、8が中立(範囲外の値をNullとして扱う)。上位4ビットは0 |
| 5〜8 | X、Y、Z、Rz。符号付きで-127〜127、YとRzは下が正 |

レポートディスクリプタはGeneric DesktopのGamepad(0x05)で、ボタン、ハット、軸を1つのレポートにまとめています。軸は絶対値、ボタンは1ビットの可変フィールドです。アプリケーションの用途と各フィールドを見てゲームパッドかどうかを判定するHIDドライバ(超漢字のusbplusなど)も、そのままゲームパッドとして扱えます。

### 送り方

- キー処理(`kb_process.c`)が、スキャンごとにキーボードのレポートと一緒にゲームパッドのレポートを作ります。
- ゲームパッドのレポートは、内容が変わったときに送ります。送信は待ちません。前のレポートがまだホストに読まれていなければ、次のスキャンで最新の状態を送り直します。BIOSの画面など、ホストがゲームパッドのエンドポイントを読まない場合でも、キーボードの送信は遅れません。
- USBのデバイス`usbk`では、データ番号`USB_HID_DN_PAD`(1)に`T_USB_HID_PAD_REPORT`を書くとゲームパッドのレポートになります(`device/include/dev_usb_hid.h`)。データ番号0はこれまでどおりキーボードです。
- H533でwasmのキー処理を使っている間は、ゲームパッドは中立のままです。wasmのキー処理はキーボードのレポートだけを作るためです。

| ファイル | 内容 |

| `device/usb_hid/usb_hid_class.c` | ゲームパッドのディスクリプタ、インタフェースへの要求の処理、送信 |
| `device/usb_hid/usb_hid.h` | インタフェース番号、エンドポイント、構成ディスクリプタの長さ |

## 制限

- スティックはキーで倒すので、端か中央かのデジタル入力だけです。ADCによるアナログ入力には対応していません。
- BLEで接続しているときは、ゲームパッドのレポートは送りません(USBのみ)。
- STM32H7ではUSBの下位層がEP3に対応していないため、`GAMEPAD=1`はビルドエラーになります。
- XInput(Xbox 360方式)ではなく、汎用のHIDゲームパッドです。XInputにしか対応しないゲームでは、Steamの入力設定などで変換してください。ゲームによっては、ボタンの割り当てを自分で設定する必要があります。
- ビルドと、PC上でファームウェアのディスクリプタとレポートをHIDの解析処理に通す検証までを確認しています。実機をUSBでつないだ状態での確認はまだです。
